# Алгоритм шифрования МиниГОСТ

## Назначение и параметры

МиниГОСТ в данном проекте — учебный блочный шифр с сетью Фейстеля. Он используется как малый экспериментальный объект для исследования линейных вероятностных соотношений и восстановления раундовых подключей. Это не реализация стандартизованного шифра «Магма» и не средство защиты реальных данных.

| Параметр | Значение |
| --- | --- |
| Размер блока | 16 бит |
| Полублоки | Два по 8 бит |
| Основной ключ | 32 бита, четыре байта |
| Число раундов | 12 |
| Число возможных пар двух последних 8-битных подключей | 65 536 |

## Раундовое преобразование

Пусть вход раунда состоит из левого и правого байтов `(L, R)`, а `k` — используемый в этом раунде байт ключа. Для исходного варианта шифра функция имеет вид

```text
F(L, k) = P((L + k) mod 256),
(L, R) -> (R XOR F(L, k), L).
```

Здесь `P` сначала подставляет оба четырёхбитных полубайта по отдельным таблицам, затем циклически сдвигает полученный байт влево на пять бит. Старший полубайт преобразуется по `p1`, младший — по `p0`:

```text
p1 = [12, 4, 6, 2, 10, 5, 11, 9, 14, 8, 13, 7, 0, 3, 15, 1]
p0 = [ 6, 8, 2, 3,  9, 10, 5, 12,  1, 14, 4, 7, 11, 13, 0, 15]

s = (p1[x >> 4] << 4) | p0[x & 0x0F]
P(x) = ((s << 5) | (s >> 3)) & 0xFF
```

Например, для `x = 0x93` после подстановки получается `0x83`, а после сдвига — `0x70`. В реализации значения `P(x)` для всех 256 входов сохранены в таблице `PREP_PHASE_TABLE`. Таблицу порождает `tools/prep_phase.py`.

## Расписание ключа и шифрование

Основной ключ передаётся в функцию как массив четырёх байтов `key[0..3] = (K^(4), K^(3), K^(2), K^(1))`. Подключи раундов с первого по двенадцатый выбираются по индексам

```text
3, 2, 1, 0, 3, 2, 1, 0, 0, 1, 2, 3.
```

Таким образом, порядок обозначенных подключей: `K^(1), K^(2), K^(3), K^(4), K^(1), K^(2), K^(3), K^(4), K^(4), K^(3), K^(2), K^(1)`. Последние два раунда используют `K^(2)` и `K^(1)`.

Входной 16-битный блок разделяется на старший байт `L_0` и младший байт `R_0`. Описанный раунд применяется 12 раз. После двенадцатого раунда полублоки меняются местами: выходной блок составляется из `(R_12, L_12)`. Эта заключительная перестановка является частью определения шифрования, а не дополнительным раундом.

## Расшифрование

Расшифрование начинает с обратной перестановки двух байтов шифртекста. Затем раунды выполняются в обратном порядке подключей. Обратное преобразование одного раунда для его выходного состояния `(L', R')` имеет вид

```text
(L', R') -> (R', L' XOR F(R', k)).
```

Обратная функция `P` не требуется: обратимость обеспечивается конструкцией Фейстеля. Реализация `minigost_decrypt_block` применяет именно эту процедуру.

## Вариант с XOR-введением подключа

В отдельной серии экспериментов изменяется только операция введения байта ключа **внутри** раундовой функции:

```text
F_xor(L, k) = P(L XOR k).
```

Структура раунда `(L, R) -> (R XOR F_xor(L, k), L)`, число раундов и расписание подключей остаются прежними. Поэтому XOR-введение подключа не следует путать с XOR между полублоком и выходом `F`, присутствующим в обоих вариантах.

## Область применения и реализация

Малый размер блока позволяет экспериментально перебрать все `2^16` открытых текстов, а два последних байтовых подключа — проверить все `2^16` пар-кандидатов. Эти параметры выбраны для статистического исследования, а не для практической криптографической стойкости.

Исходное шифрование и расшифрование реализованы в `src/minigost.c`; интерфейс объявлен в `include/minigost.h`. Режим ECB в той же реализации обрабатывает независимые двухбайтовые блоки в порядке старший байт — младший байт. Он не используется как доказательство безопасности и не рекомендуется для защиты данных.

Для проверки параметров и таблицы следует обращаться к `src/minigost.c`, `include/minigost.h` и `tools/prep_phase.py` в этом же репозитории. Экспериментальная процедура восстановления ключа отдельно описана в `docs/key_recovery_study_method.md`.
