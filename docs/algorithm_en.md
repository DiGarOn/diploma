# MiniGOST Block Cipher Specification

## Purpose and parameters

MiniGOST is the educational Feistel block cipher used in this project's experiments on linear probabilistic relations and round-key recovery. It is not an implementation of the standardized Magma cipher and is not intended to protect real data.

| Parameter | Value |
| --- | --- |
| Block size | 16 bits |
| Half-block size | 8 bits |
| Master key | 32 bits, represented by four bytes |
| Number of rounds | 12 |
| Candidate pairs for the final two 8-bit round keys | 65,536 |

## Round transformation

Let `(L, R)` denote the left and right bytes at the input of a round, and let `k` be that round's key byte. In the original cipher, the round function and state update are

```text
F(L, k) = P((L + k) mod 256),
(L, R) -> (R XOR F(L, k), L).
```

The transformation `P` substitutes the high and low four-bit nibbles separately and then rotates the resulting byte five bits to the left. The high nibble uses `p1`, and the low nibble uses `p0`:

```text
p1 = [12, 4, 6, 2, 10, 5, 11, 9, 14, 8, 13, 7, 0, 3, 15, 1]
p0 = [ 6, 8, 2, 3,  9, 10, 5, 12,  1, 14, 4, 7, 11, 13, 0, 15]

s = (p1[x >> 4] << 4) | p0[x & 0x0F]
P(x) = ((s << 5) | (s >> 3)) & 0xFF
```

For example, `x = 0x93` becomes `0x83` after substitution and `0x70` after rotation. The implementation stores `P(x)` for all 256 inputs in `PREP_PHASE_TABLE`, generated by `tools/prep_phase.py`.

## Key schedule and encryption

The master key is passed as four bytes, `key[0..3] = (K^(4), K^(3), K^(2), K^(1))`. Rounds one through twelve select key-array indices in this order:

```text
3, 2, 1, 0, 3, 2, 1, 0, 0, 1, 2, 3.
```

Thus the round-key sequence is `K^(1), K^(2), K^(3), K^(4), K^(1), K^(2), K^(3), K^(4), K^(4), K^(3), K^(2), K^(1)`. The final two rounds use `K^(2)` and `K^(1)`.

An input block is divided into its high byte `L_0` and low byte `R_0`. After twelve applications of the round transformation, the two half-blocks are swapped. The ciphertext consists of `(R_12, L_12)` in high-byte, low-byte order. This final swap is part of encryption, not an additional round.

## Decryption

Decryption first reverses the final swap and then processes the round keys in reverse order. The inverse of one round, applied to its output `(L', R')`, is

```text
(L', R') -> (R', L' XOR F(R', k)).
```

An inverse of `P` is unnecessary because the Feistel construction makes the round reversible. The implementation of `minigost_decrypt_block` follows this procedure.

## XOR key-injection variant

In a separate set of experiments, only the operation that combines the round-key byte with the input **inside** the round function changes:

```text
F_xor(L, k) = P(L XOR k).
```

The Feistel update `(L, R) -> (R XOR F_xor(L, k), L)`, the number of rounds, and the key schedule remain the same. XOR key injection inside `F_xor` must not be confused with the XOR between the half-block and the output of the round function, which occurs in both variants.

## Scope and implementation

The small block allows all `2^16` plaintexts to be enumerated, while the final two byte-sized round keys allow all `2^16` candidate pairs to be tested. These parameters serve the statistical study; they do not imply practical cryptographic strength.

The original encryption and decryption functions are implemented in `src/minigost.c`, with their public interface in `include/minigost.h`. The same implementation also provides an ECB mode that processes independent two-byte blocks in high-byte, low-byte order. ECB is not a security claim and is not recommended for protecting data.

The source of truth for the cipher parameters and substitution table is `src/minigost.c`, `include/minigost.h`, and `tools/prep_phase.py` in this repository. The separate key-recovery procedure is described in `docs/key_recovery_study_method.md`.
